Willing to understand how a public-service-subscription management system works (whether it is an app, a website...), I decided to write the Python code included in the repository.

My main interest was implementing the logic behind features such as budget estimate, sum, amount to pay and the ones which allow the user to top up their wallet. 

I tried to keep it clear and written in such a way that even a complete beginner like me can understand the process: I know about the possibility to avoid line redundancy, but for this very first code I wanted to have all the possibilities "visible" whenever they are shown in the terminal.

Besides the core functionality, I also tried to make the program as user-friendly as possible, offering, for example, the possibility to return to the main menu ("choose a service").

The activity took me about 6 hours, most of them spent on bugs adjustment. I tested the programm both through many simulations in the terminal and with AI assistance (Gemini).

I'm thankful to both of them, since the first allowed me to walk in an everyday user's shoes, while Gemini provided targeted hints ("The amount is deducted before the user confirms his purchase"), and let me search for the exact line, function, variable, controls, statements... 

Some of the most common mistakes: 

-lines put above/below the correct position, 

-input in "int" rather than "str",

-wrong indentation (especially within the very first steps).


Overall, I found (and hope it will remain so for the years to come) coding such a stimulating activity, because it doesn't allow for "shortcuts", and it is all up to the programmer: the app/website will run exactly as he/she wants only if all the logical flow is perfectly translated into the code.
